## 一句话结论

**前端是真的，后端是假的。**

说细点：

- **`index.html` 那 3558 行，是真能跑的。** 零依赖、无构建、单文件，评分/录音/语料/统计全都好使。这点他没吹牛。
- **`server/` 那 279 行，唯一的功能从没成功跑过。** 前端录音出来的是 WebM/Ogg/MP4，后端只认 WAV —— `wavefile` 源码里白纸黑字：
  ```js
  // node_modules/wavefile/lib/riff-file.js:74
  this.supported_containers = ['RIFF', 'RIFX'];
  ```
  中间**没有任何转码**。也就是说，「本地 Whisper 音素级评分」这个头号卖点，**在这条链路上不可能成功**：每次调用必 500，然后被前端静默吞掉、退回浏览器识别。
  （严谨起见：此结论基于代码路径 + Edge 实测，未穷举所有浏览器与版本。）
- **README 吹的 5 件事，4 件是假的。** 最离谱的是那个「214 项自动化测试通过」绿徽章 —— 测试代码从第一个 commit 起就在 `.gitignore` 里，**压根没提交过**。谁 clone 下来都跑不了，因为文件根本不存在。
- **被人当面打了脸。** issue #5 就干这个的：作者在 #1 #2 #3 下面回「bug已修复」然后关掉，但**一个 commit 都没提**。仓库至今还是 2 个 commit。

## 那怎么办

**别修，砍。**

把这堆用不了的功能删掉，README 改成实话 —— **一个新功能都不用写**，5 个 issue 全闭。

砍多少？**代码净减约 1570 行**（删 1655 行、增 83 行），而且**全砍在从没生效过的东西上，一点不碰你朋友天天在用的部分**。

具体刀法见 [PLAN.md](PLAN.md)。

## 动手前必看（这几条别跳过）

1. **两处 bug 修复已在真实浏览器验证通过。** 麦克风泄漏已复现、修好、复测（`phase` 保持 `recording`、守卫仍有效）；弹窗泄漏也已验证（`recOn` 复位、麦克风关闭）。**回归测试显示评分结果与改动前完全一致。**
2. **`file://` 下麦克风其实能用** —— 我一开始照抄 issue #1 的说法，实测推翻了。MDN 规范白纸黑字：`file` scheme 属于可信来源，是安全上下文。实测 `file://` 与 `http://127.0.0.1` 行为完全一致。**但授权提示确实缺失**，用户会一脸懵，所以推荐路径仍然该给。
3. **`Recorder.cancel()` 能正常停麦克风** —— 静态审计说它是"死代码陷阱"，实测证伪。已用于 `closeModal()` 的修复。
4. **砍了 `server/` 得补个替代方案。** README 里建议写上 `python -m http.server` 这种零安装方案。
5. **作者还不知道这事。** 你要删的是他唯一的"高级功能"卖点。建议先打个招呼，别让他从 PR 通知里发现自己被抄了家。

> **教训**：上面第 2、3 条都是"先照抄结论、后实测推翻"。静态分析的结论**没跑过就不该进文档**。
