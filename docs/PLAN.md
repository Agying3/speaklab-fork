## 一、移除本地 Whisper 引擎

**为什么**：这条链路从设计上就跑不通，不是配置问题。前端录音产出的是 WebM/Ogg/MP4，后端只认 WAV，中间没有任何转码 —— 每次调用必然失败，然后被前端静默吞掉、退回浏览器识别。

**做什么**：删掉 `server/` 整个目录，以及前端与之相关的接线（引擎切换对象、设置页入口、状态提示、音素判定的对应分支）。

**影响**：用户侧零损失 —— 这些功能本来就不可用。

## 二、修复两处真实缺陷

| 缺陷 | 表现 |
|---|---|
| 录音中点「下一句」 | 界面回到待录状态，但录音器仍在跑。**麦克风无法停止**，直到关闭页面 |
| 关闭练习弹窗时正在录音 | 录音器与识别都不停；且内部跟读标记卡住，导致下次点击跳过录音、拿上次的旧文本打分 |

两处都已修复，并在真实浏览器中复现、修复、复测。

## 三、README 改为如实描述

原 README 有五处声明与实现不符，其中最典型的是「214 项自动化测试通过」徽章 —— 测试代码从未提交，克隆下来根本跑不了。

改法：删掉无法成立的声明，保留确实成立的（如前端零 CDN），把联网范围说清楚。

## 四、新增「声纹行情」互动模块

**做什么**：把麦克风实时基频（音高）画成 K 线走势图，红涨绿跌，从右向左滚动，超出左边界的历史自动裁掉。纯前端实现，不依赖后端。

**为什么加**：原项目只给"读得对不对"打分，不涉及**语调**——而英语的升调疑问、降调陈述、重音位置恰恰是中文母语者最明显的短板。音高曲线本是发音教学的常规工具，这里做成可视化形态。

**实现要点**：
- 独立的 `getUserMedia` + `AudioContext` 采集链路，**不复用** `Recorder`，避免与跟读/对话录音互相干扰
- 基频检测采用 YIN 的 CMNDF 算法（差值函数 + 累积均值归一化 + 首个低谷 + 抛物线插值）
- 每 110ms 聚合一根 K 线；静音不产生新 K 线
- 离开页面自动停止采集

**已验证**：基频在 75–410Hz 区间实测**零误差**；K 线数量恒定为可视上限、旧数据确实被移除；与原有功能的回归对照一致。

## 不做的事

- **不修 Whisper 链路** —— 需要引入音频编码/解码，工作量大且随功能删除而问题消失
- **不补测试框架** —— 超出本次范围
- **不重构评分逻辑** —— 现有实现可用，无必要动

基线测试 → 建分支 → 删引擎 → 修缺陷 → 改 README → 回归对照 → 零残留检查 → 提交 → PR

```

2. README 改为如实描述

```

> 前两项的代码改动同处一个文件，按文件粒度无法拆开，故合并提交并在说明中分段叙述 —— 不做内容重叠的假拆分。
